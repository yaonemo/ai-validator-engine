# 培训技能包（Trainer Officer）

> 三角色之一：**培训**（规则→填表说明）→ **核对**（数据→校验）→ **复盘**（数据→洞察+报告+学习）
> 本技能是「培训」角色的方法论：把总部的规则文档翻译成人人看得懂的说明书。

## 这个技能是干什么的

把部门的标准/规则文档，翻译成**两种人看的说明书**：

- **项目版**：给一线填表的人看——具体怎么做、每格填什么、最容易错在哪、填错了怎么改
- **事业部版**：给事业部管理者看——为什么做、管什么指标、怎么验收、重点盯哪

**核心思想：同一个规则，两种语言。**
- 事业部版讲「为什么」和「管什么」（偏管理）
- 项目版讲「怎么做」和「别踩什么坑」（偏操作，每格给正例反例）

## 触发条件

用户说以下任意一种：
- "把XX规则翻译成填表说明"
- "给项目发填表指引"
- "培训材料 / 下发规则"
- "生成填表说明书"

## 工作流程

### 第 1 步：读规则文档，理解意图

通读部门标准文档，抓住三点：
1. 这项任务背后的**管理目的**是什么？（规则不是凭空来的）
2. 数据要**管什么**？（字段、流程、交付物）
3. 项目最容易**在哪个环节出问题**？（从核对技能积累的高频错误里找）

### 第 2 步：生成项目版说明书（给一线）

语言：大白话，操作导向。结构：

```
【要做什么】一句话说清
【怎么做】步骤 1 2 3
【每格怎么填】每个字段给正例 + 反例
【最容易错的地方】提前预警（来自核对技能的高频错误）
【截止时间】
【填错怎么办】提交后系统自动检查，错了会告诉你改哪里
```

**正例反例要求（必做）：**
- ✅ 正例：产权类型填「业主产权车位」
- ❌ 反例：产权类型填「个人所有」（这是错的，不在选项里）

### 第 3 步：生成事业部版说明书（给管理者）

语言：偏管理，讲「为什么」和「管什么」。结构：

```
【这项任务的管理目的】为什么总部要收这个数据
【事业部要关注什么】哪些指标、哪些项目
【项目容易在哪出问题】高频错误 TOP3（来自核对技能）
【验收标准】什么算合格
【红线】哪些错误必须返工
```

### 第 4 步：配套生成「提交前自检清单」

给一线一个提交前 30 秒自检清单（像登机牌）：
- 三大字段匹配关系（最容易错）
- 必填项有没有漏
- 示例行删了没
- 空置/无收费的特殊规则

## 注意事项（Pitfalls）

1. **项目版绝不写术语**：「校验」「预定义值域」要翻成「检查」「下拉选项里选」
2. **正例反例必须给**：一线看 100 个字不如看 1 个对 1 个错
3. **高频错误提前预警**：核对技能跑过几轮后，把高频错误写进培训材料（复盘→培训闭环）
4. **语气是帮助不是指责**：不说「你们填错了」，说「这里容易填错，注意一下」
5. **说明书和核对配置要一致**：培训说什么，核对就查什么，不能两张皮

## 验证清单

- [ ] 项目版：一线照着能填完（不用问人）
- [ ] 项目版：每个字段有正例反例
- [ ] 事业部版：管理者知道管什么、怎么验收
- [ ] 自检清单：30 秒能过一遍
- [ ] 与核对配置一致（无矛盾）
