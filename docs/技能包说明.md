# AI 技能包说明：让 AI 帮你 1 天搭起校验体系

> 这是本项目「换部门 = 换规则」的核心机制。
> 你不需要自己写规则代码——**把部门标准文档交给 AI，AI 生成规则，引擎执行**。

## 原理

```
你的部门标准文档（规则说明/培训手册/检查清单）
        │  ① 喂给 AI
        ▼
AI 按本技能包的方法，生成规则 JSON
        │  ② 生成
        ▼
rules/你的规则.json
        │  ③ 引擎执行
        ▼
python run.py 你的数据.xlsx 你的规则.json
```

## 你只需要做 3 件事

1. **准备一份「部门标准文档」**：把你部门现在用的规则说明、培训手册、检查清单整理成文字（Word/Markdown/PDF 都行）
2. **找一个 AI 助手**：Hermes / TRAE / Kimi / 文心 / ChatGPT 都行
3. **把下面的提示词 + 你的标准文档 一起发给 AI**

## 提示词模板（直接复制使用）

```
你是一个「校验规则工程师」。请根据我提供的部门标准文档，生成一份校验规则 JSON，
用于让通用校验引擎自动检查我部门的数据表格。

要求：
1. 输出 JSON 格式，包含以下部分：
   - meta：规则名称、版本、适用业务、规则来源
   - structure.标准表头：数据表格的列名（按实际表头）
   - 字段校验：每个字段的检查规则（必填、取值范围、格式）
   - 逻辑校验：字段之间的逻辑关系（如 A=XX 时 B 必须=YY）
   - 场景校验：特定业务场景的组合检查

2. 规则类型可选：required（必填）、in_list（取值必须在列表内）、
   numeric（必须是数字）、if_then（条件成立时断言必须成立）、
   personal_name_warn（疑似个人姓名警告）、org_name_check（必须是公司名）、
   keyword_not、keyword_if、keyword_and（备注关键词触发检查）

3. severity 用 error（必须改）或 warning（建议改），
   每条规则 message 要写成人话，告诉填表人「哪个字段、当前值、应该怎么改」

4. 不确定的规则标 severity: warning，不要乱报 error

5. 先输出规则 JSON，再输出一段 50 字以内的说明：这份规则覆盖了哪些检查点。
```

## 生成后做什么

1. 把 AI 输出的 JSON 保存为 `rules/你的规则.json`
2. 跑一次：`python run.py 你的数据.xlsx 你的规则.json`
3. 看结果：该报的错报了吗？不该报的误报了吗？
4. 把误报的规则描述反馈给 AI 让它修正，一般 1-2 轮就稳定
5. 规则稳定后固化，之后每次收数据直接跑

## 为什么这样能「1 天搭建」

- 规则生成：AI 读文档 → 10-30 分钟出初稿
- 规则校准：AI 跑数据看误报 → 1-2 轮修正
- 部署运行：装 Python + 依赖 + 跑通 → 半天内
- **总计：1 天左右，一个部门就能拥有自己的自动校验体系**

## 进阶：完整闭环（可选）

引擎只是「核对」环节。完整的「培训-核对-复盘」闭环需要 AI 工作台（如 Hermes Agent）：

- **培训**：规则自动翻译成话术，直达填报人
- **核对**：本引擎自动执行，结果自动通知
- **复盘**：错误模式自动统计，反哺规则优化

如需部署完整闭环，联系方案作者获取技能包部署指引。
